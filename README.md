# Jeonghan Daily Review Bot v3.1

دستیار خصوصیِ Review-only برای کانال دیلی یون جونگهان:

- هر ۱۵ دقیقه منابع منتخب X و جست‌وجوی عمومی را بررسی می‌کند.
- آپدیت‌های مشابه را از چند منبع با هم ادغام می‌کند تا عکس یا ویدیو جا نماند.
- با Gemini و در صورت تنظیم بودن با Groq، ترجمه و کپشن فارسی می‌سازد.
- برای پست‌های چندعکسی تا چهار تصویر را هم‌زمان به Gemini می‌دهد تا واکنش فقط بر اساس عکس اول نباشد.
- لحن را از `style_guide.md` و ۱۶۶۰ نمونهٔ واقعی `channel_memory.jsonl` می‌گیرد.
- مدیا، کارت بررسی و نسخهٔ تمیزِ آمادهٔ فوروارد را فقط به چت خصوصی ادمین می‌فرستد.
- هیچ پستی را خودکار داخل کانال منتشر نمی‌کند و لازم نیست ادمین کانال باشد.
- آلبوم‌های سنگین را با سقف امن تکه‌تکه می‌کند؛ خطای یک عکس/ویدیو کل اجرای بات را متوقف نمی‌کند.

## دکمه‌ها و دستورهای تلگرام

روی هر پیش‌نویس قابل انتشار:

- `😂 بامزه‌تر`: بازنویسی با هیومر بیشتر، بدون تغییر واقعیت.
- `🪽 نرم‌تر`: نسخهٔ صمیمی‌تر و لطیف‌تر.
- `📰 دقیق‌تر`: نسخهٔ خبری‌تر با حداقل شوخی.
- `✍️ ویرایش دلخواه`: بعد از زدن دکمه، خواسته‌ات را با زبان معمولی بفرست؛ مثلاً «کوتاه‌تر و شیطون‌تر».
- `✅ فرستادم`: بستن پیش‌نویس بعد از فوروارد دستی.
- `🗑 رد`: کنار گذاشتن پیش‌نویس.

دستورها:

- `/status`: زمان آخرین اجرای موفق، تعداد پیش‌نویس‌های باز و آمار اجرا.
- `/pending`: فهرست پیش‌نویس‌های باز.
- `/edit ID درخواست`: ویرایش مستقیم یک پیش‌نویس با دستور دلخواه.
- `/cancel`: لغو حالت ویرایش دلخواه.
- `/help`: راهنمای کوتاه داخل تلگرام.

سریع‌ترین راه ویرایش دلخواه این است که مستقیم روی همان کارت پیش‌نویس Reply کنی و
خواسته‌ات را بنویسی؛ بات Reply را به همان پیش‌نویس وصل می‌کند و در اجرای بعدی نسخهٔ تازه را می‌فرستد.

دکمه‌ها با اجرای بعدی GitHub Actions پردازش می‌شوند؛ پس پاسخ ممکن است تا حدود ۱۵ دقیقه طول بکشد.

## فایل‌ها را کجا بگذارم؟

محتوای بسته را دقیقاً در ریشهٔ Repository آپلود کن و ساختار پوشه‌ها را نگه دار:

```text
.github/workflows/main.yml
jeonghan-daily-review-bot-v2/
  config.yml
  requirements.txt
  style_guide.md
  data/channel_memory.jsonl
  src/bot.py
  state/state.json
  tests/test_bot.py
  tests/test_package.py
```

Secretهای فعلی با جایگزین کردن فایل‌ها پاک نمی‌شوند. پوشهٔ قدیمی و تو‌در‌توی
`jeonghan-daily-review-bot-v2/.github/` دیگر لازم نیست؛ فقط ورک‌فلوی ریشه اجرا می‌شود.

## Secretهای لازم در GitHub

در `Settings → Secrets and variables → Actions`:

- `TELEGRAM_BOT_TOKEN`
- `TELEGRAM_REVIEW_CHAT_ID`
- `TELEGRAM_ADMIN_USER_ID`
- `X_COOKIE`
- `GEMINI_API_KEY` برای تنظیم پیش‌فرض فعلی
- `GROQ_API_KEY` اختیاری، برای fallback رایگان در صورت خطای Gemini

مدل اصلی `gemini-3.5-flash-lite` است. fallback اختیاری Groq روی
`openai/gpt-oss-120b` تنظیم شده؛ مدل قبلی `llama-3.3-70b-versatile` در
۱۶ اوت ۲۰۲۶ برای پلن رایگان خاموش می‌شود.

برای چت خصوصی معمولاً `TELEGRAM_REVIEW_CHAT_ID` و `TELEGRAM_ADMIN_USER_ID` یک عدد هستند.
مقادیر واقعی را داخل فایل، Commit، Issue یا چت عمومی نگذار. فایل `.env.example` فقط نام متغیرها را نشان می‌دهد.

## تنظیم منابع

در `config.yml`، username را بدون `@` بنویس:

```yaml
sources:
  - username: "example_account"
    enabled: true
    require_keywords: true
    trust_score: 0.80
```

- `require_keywords: false` فقط برای اکانتی مناسب است که کاملاً مخصوص جونگهان باشد.
- `trust_score` امتیاز اولویت منبع است، نه برچسب «رسمی».
- جست‌وجوی عمومی سقف جداگانه دارد تا چت خصوصی با پیش‌نویس‌های کم‌اهمیت پر نشود.
- موارد اضافه حذف نمی‌شوند؛ در اجرای بعدی بررسی می‌شوند، مگر اینکه از سقف عمر backlog بگذرند.

## اجرای GitHub Actions

ورک‌فلو دو حالت دستی دارد:

- `live`: تست فایل‌ها و سپس اجرای واقعی بات.
- `check`: فقط نصب، اعتبارسنجی و اجرای تست‌ها؛ هیچ تماس زنده‌ای با X، تلگرام یا AI ندارد.

اجرای زمان‌بندی‌شده همیشه `live` است. وضعیت بات بین اجراها با GitHub Actions Cache نگه داشته می‌شود؛
بنابراین دکمه‌ها، پست‌های دیده‌شده و پیش‌نویس‌های باز بعد از پایان هر Runner از بین نمی‌روند.

در اجرای اول حداکثر ۵ پیش‌نویس ساخته می‌شود تا بات ناگهان backlog قدیمی را داخل چت نریزد.

## کنترل کیفیت و ایمنی

- فایل تنظیمات پیش از اتصال به سرویس‌ها اعتبارسنجی می‌شود.
- تست‌های آفلاین تنظیمات، workflow، ادغام منابع، حافظهٔ لحن، حریم خصوصی، ویرایش دلخواه، مهاجرت state و fallback خطای واقعی `Telegram 413` را پوشش می‌دهند.
- متن X به‌عنوان دادهٔ غیرقابل‌اعتماد به مدل داده می‌شود تا دستورهای مخرب داخل پست نتوانند پرامپت را عوض کنند.
- محتوای دارای ریسک حریم خصوصی نسخهٔ قابل فوروارد نمی‌گیرد.
- اگر هر دو مدل AI از دسترس خارج شوند، منبع برای بررسی دستی می‌آید ولی متن خام به‌عنوان کپشن آماده منتشر نمی‌شود.
- خطاها پیش از ارسال به تلگرام از نظر Token، Cookie و API key پاک‌سازی می‌شوند.
- کپشن‌های بلند مدیادار بدون قطع شدن، به‌صورت مدیا و پیام تمیز بعدی ارسال می‌شوند.
- عکس‌ها زیر ۹MB، ویدیوها زیر ۴۴MB و هر درخواست آلبوم زیر ۴۴MB نگه داشته می‌شود؛ اگر آلبوم باز هم رد شود، آیتم‌ها جداگانه ارسال و لینک منبع حفظ می‌شود.
- شناسهٔ آپدیت و پیش‌نویس قبل از آپلود مدیا در state ذخیره می‌شود؛ بنابراین خطای مدیا باعث تکرار همان پیش‌نویس در اجرای بعدی نمی‌شود.

## عیب‌یابی سریع

1. از تب `Actions`، ورک‌فلو را با حالت `check` اجرا کن.
2. اگر سبز شد، یک‌بار حالت `live` را اجرا کن.
3. داخل چت خصوصی بات `/status` بفرست؛ پاسخ در اجرای بعدی می‌آید.
4. اگر دریافت X خطا داد، معمولاً `X_COOKIE` منقضی شده یا X endpoint خود را تغییر داده است.
5. اگر Gemini خطا داد، کلید و quota را بررسی کن؛ در صورت وجود `GROQ_API_KEY` fallback خودکار است.

برای بررسی محلی بعد از نصب وابستگی‌ها:

```bash
python -m src.bot --check
python -m unittest discover -s tests -v
```

## نکات امنیتی

- Repository عمومی است؛ فقط محتوای عمومی کانال را در حافظه و راهنمای لحن بگذار.
- برای X از اکانت فرعی استفاده کن.
- Cookie یا کلیدها را هرگز داخل `.env.example` ننویس.
- اگر Secret قبلاً جایی عمومی شده، حذف فایل کافی نیست؛ همان Secret را فوراً rotate کن.
